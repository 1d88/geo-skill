# 报告与优先级规范

## 交付物

每轮审计输出四部分：

1. **范围与限制**：目标环境、采集时间、URL 来源、样本规则、是否完成浏览器渲染、无法访问的内容。
2. **基线摘要**：已检查 URL 数、状态码分布、可索引信号、canonical 冲突、关键内容只在客户端出现的页面数。
3. **问题清单**：每项必须包含唯一 ID、优先级、URL/模板、实际证据、潜在影响、修复建议、验收条件和复测方法。
4. **执行计划**：按依赖与投入分批，建议分为阻断项、快速收益项、模板级改造和长期监测。

## 优先级

- **P0**：大范围阻断抓取或错误阻止索引，且证据明确；立即处理。
- **P1**：影响关键页面或整类模板的索引信号、canonical、状态码、正文或内部链接问题。
- **P2**：影响有限，或主要降低搜索摘要质量、结构理解和站内发现效率。
- **P3**：改进项或证据不足的假设；先验证，不应挤占确定性更高的问题。

修复成本使用 `S / M / L`。在同一优先级内，先排影响页面更多、业务价值更高、成本更低和证据更强的项。

## 单条发现格式

- ID 和标题
- 优先级、修复成本、置信度
- 受影响 URL 或页面模板
- 实际证据（状态、标签值、HTML 摘要或原始/渲染差异）
- 影响（使用“可能”描述合理风险，不宣称未经验证的排名损失）
- 建议改法
- 验收条件
- 复测命令或操作

## Search Console 验证

只有获得 Search Console 数据后，才增加“实际收录与搜索表现”章节。记录所用属性、时间范围、过滤条件和数据延迟。修复后先验证技术信号，再在合理观察窗口比较索引覆盖和查询表现；保留季节性、内容变化、竞争环境等混杂因素。
