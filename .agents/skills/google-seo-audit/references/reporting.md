# 报告与优先级规范

## 先明确结论等级

对每条可核查断言分别定级，而不是给整个网站一个模糊的“高置信度”：

- `verified` / **已验证**：在注明的 URL、时间和采集口径内，有直接证据且关键反证已处理。可以肯定技术事实或 Google 返回的记录，不能把有限事实扩大为排名因果。
- `supported` / **证据支持，尚不能确定**：存在支持数据，但采样、时间滞后、混杂因素或冲突尚未排除。写清支持什么、还缺什么，不能表述为已证实收益或故障。
- `unknown` / **无法确定**：没有适用数据、请求失败、未检查或关键来源校验失败。写最小补证步骤，不把缺失解释为零。

每项同时注明证据来源为网站现场、Google 索引记录或搜索表现。不同来源回答不同问题，不能相互替代。“页面 noindex 已移除”可以 verified，同时“Google 已重新索引”仍是 unknown；不要因后者未知而否定前者。

## 交付报告

1. **结论摘要**：先列已验证事实，再列有支持但未定论事项和无法确定事项，标注数量、范围及最关键限制。无某类结论时写“无”，不凑数。
2. **任务与覆盖**：任务 ID、模式、skill 版本、采集/分析时间、环境、实际参数；sitemap 数、递归新增数、去重与已检查数、深度、limit、遗漏/排除、模板/语言覆盖和渲染成功率。来源缺少统计字段时标为不可得，不猜分母。
3. **证据与结论表**：ID、断言、等级、URL/范围、来源文件及 JSON 字段/HTML 片段、证据时间、反证或缺口。用户应能沿引用复核结论。
4. **优化行动清单**：只放可复现、有行动价值的问题；给具体页面/模板、建议改法、优先级、成本、技术验收方法和需要 Google 后续验证的条件。未获修改授权时明确为建议。
5. **复测与反馈**：有基线则按稳定 ID 列 `fixed / remaining / new / not_tested`，给前后值与证据。没有基线则列下轮采集触发条件，不伪造变化。

GSC 可用时在证据部分写属性、日期窗口、实际过滤器、索引抽检分母和数据延迟。不可用时用一行说明，技术审计照常完成。采集器故障按来源汇总到证据缺口，避免逐 URL 重复错误淹没主要结论。

## 优先级与结论等级分开

- **P0**：已确认的大范围抓取阻断或错误阻止索引。
- **P1**：关键页面或模板的状态码、索引信号、canonical、正文或内部链接问题。
- **P2**：有限范围问题，或影响搜索摘要质量、结构理解、页面发现效率的问题。
- **P3**：有证据和具体收益目标的非阻断改进。

成本用 `S / M / L`；同级按范围、已知业务价值和成本排序。证据不足的假设进入待验证项，不因怀疑严重就创建 P0–P3 修复任务。严重度不等于确定性。

## GSC 交叉验证与冲突处理

读取 [GSC 规范](search-console.md)，逐项对齐 URL、属性、时间与字段。

- 当前 HTML 自引用 canonical，但 Google 的 googleCanonical 指向其他 URL：两项观察可分别已验证；解释先比较 Google 抓取时间，不能直接宣称网站当前 canonical 设置错误或 Google 已采纳。
- 技术修复通过，但 lastCrawlTime 早于发布：技术可记 fixed；Google 验证写等待重抓，不判修复失败。
- 同口径窗口 clicks 上升：数值变化可已验证；“这次 SEO 修复导致增长”仍未证实。记录发布、季节性、品牌需求、内容变化等已知混杂因素，不虚构排除结果。
- 页面明细无某 URL：只能确定该查询没有返回该行，不能推断零流量或未收录。需要索引状态时查看该 URL 的 Inspection 记录。
- 本地、浏览器或 Google 证据冲突且时间差无法解释：保留原始值与冲突，缩小断言范围，给最小复查步骤，不能选择性忽略反证。

只对实际检查的 URL 下索引结论，不以 Inspection 样本推算全站覆盖率。确认技术修复、确认 Google 记录变化、确认搜索指标变化分别报告。GSC 不能证明 AI 搜索引用、推荐或 GEO 效果。
